# Challenges

**A published vector is a constant, and a remembered one is a guess.** The first version of the GCM tests carried four vectors from memory. Two of them passed immediately and two failed, and the obvious reading was that the implementation was wrong for messages longer than one block. It was not: the implementation was right and two of the remembered constants were wrong. The reference implementation settled it in one run -- asked what the published inputs actually produce, it returned the published ciphertext and the published tag, and the code matched both. The lesson is not "be careful with constants". It is that a test whose expected value came from the same head as the code is not an external check at all, and the only way to tell the difference is to ask something that was not involved. Every vector in the suite now reproduces against the reference implementation before it is pinned, and the four GCM cases are asserted against the values NIST publishes rather than the values this repository remembers.

**The shortest published cases hide the longest bug.** The first two GCM examples hash a single block each. An implementation with a broken GHASH can reproduce both of them, because neither one exercises the chaining that a longer message needs -- and a suite built only from those two would go green on code that is wrong for every real message. The differential test exists for that: several hundred random inputs, every nonce length the reference accepts, plaintexts and associated data from empty to a few hundred bytes, all compared against an implementation written by somebody else.

**The bit ordering in GHASH is invisible until it is wrong.** Multiplication in GF(2**128) as the specification defines it shifts to the right and applies the reduction polynomial when the low bit falls off, because the bit numbering runs the opposite way to the obvious one. Written the obvious way, the arithmetic is still self-consistent -- it multiplies, it reduces, it produces a value -- and every tag is wrong. Nothing about the output says "wrong"; it looks like a tag. That is the property that makes a hand-written cipher harder to trust than a borrowed one, and it is why the vectors and the oracle both have to be there.

**A skipped test is a false sense of safety.** The differential tests originally skipped when the reference implementation was absent, which meant a machine without it ran a suite that looked complete and had quietly stopped checking the thing that matters most. A missing oracle is now a failure with a sentence explaining what is missing. The reference is declared in `requirements.txt`, so a correct environment has it, and an incorrect one says so out loud.

**What is not here is as much a part of the design as what is.** There is no RSA, no ECDSA, no key exchange and no post-quantum implementation yet, and the README says so in the same place it says what the code does. A toolkit that describes itself as complete while half the primitives are missing is worse than one that names the gap, because the first is a claim a reader cannot check and the second is one they can.
