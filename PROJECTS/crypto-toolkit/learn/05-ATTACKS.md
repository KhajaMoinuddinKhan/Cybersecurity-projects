# The four attacks

**Length extension.** A MAC built as `sha256(secret || message)` looks reasonable and is forgeable. SHA-256's digest *is* its internal state, the padding it appends is public, and a state can be continued -- so anyone who has seen one message and its tag, and who knows the secret's length, can compute a valid tag for `secret || message || padding || appendage`. The attack needs the length and not the value because the length is what determines the padding it has to reproduce. The fix is not a different hash: it is HMAC, where the secret is used at both ends so the state an attacker resumes is not the state verification will compute. The test that matters most here is the negative one, where the same extension is applied to an HMAC and does not verify.

**GCM nonce reuse.** Three things fail in order of seriousness. The keystream is identical under a repeated nonce, so the two ciphertexts XOR to the two plaintexts XORed and one known message gives the other away. The same keystream lets an attacker encrypt under that nonce without the key. And the tag is GHASH of the message XORed with a mask that depends only on the nonce, so two tags differ by the difference of two GHASH values -- and GHASH is a polynomial in the hash subkey, so two messages give one equation in one unknown. Recover the subkey and tags can be forged for any message under that nonce, which defeats authentication even though the key was never touched. What is worth knowing is the shape of it: a single pair of messages does *not* finish the job. The difference of two tags is a polynomial whose every root in GF(2**128) is a genuine candidate, so one pair narrows the subkey to a handful and three messages under the same nonce are what pin it down.

**Padding oracle.** CBC hides a plaintext well; what breaks it is the error message. Stripping PKCS#7 padding means deciding whether it is valid, and a receiver that says which way it decided has handed over an oracle. One bit per query is enough, because the previous ciphertext block is an input the attacker controls and flipping a byte of it flips the corresponding byte of the plaintext. Driving the last plaintext byte through all 256 values until the padding validates pins it down, and knowing it makes the next byte the last one, so the block falls a byte at a time. About 128 queries per byte, no key, and the "oracle" does not have to be an error message -- a different status code or a different response time is the same thing.

**ECDSA nonce reuse.** ECDSA signs with a secret nonce k, and two signatures that used the same k share an r. Subtracting the two signing equations makes the private key cancel out of the difference and leaves k recoverable from public values; with k known, the first equation inverts straight to the private key. There is no root finding and no second message beyond the two signatures. This is why RFC 6979 exists, and why this project implements it: a nonce derived from the key and the message can never repeat. The test for the fix is that sixty signatures over random messages never repeat an r.
